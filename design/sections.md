### G1 Global — Header (Site Part "Header", ID 33) — accepted 2026-10-18
- **Build:** `e-flexbox` (`header`): logo `e-svg` (attachment 46, 117 × 35, links to `/`) → **Nav Menu** widget (`theme/widgets/nav-menu.php`, WordPress menu "Primary", Header location) → `e-button` Get Started (`btn-primary` + local styles 8/16, 12/18, radius 8 — 100 × 34, as in the design; links to Contact by ID 50). Local styles: `space-between`, padding 16/32, height 67 (= the navbar in Figma). The menu widget was inserted via the document API (D18).
- **Fix 2026-10-18 (user feedback):** on Home the button was 139 × 48 — `btn-primary` from the page's CSS file overrode `btn-small` from the header's file (D22). The button now uses a single class + local styles; burger 44 → 34 × 34 (a square as tall as the button); logo at ≤576 — 96 × 29 (SCSS), the header fits down to 320.
- **Sticky header:** the theme wrapper `.aiec-site-header` (`template-parts/header.php`), background `rgba(254,254,254,.92)` + `blur(13.5px)` — SCSS `widgets/_nav-menu.scss`; offset for the WordPress admin bar.
- **Menu:** 16/24, `#3d3d3d`; the active item is `#0e0e0e` with a full-width gray `#888` line; on hover the line grows smoothly.
- **Tablet (≤1024):** logo | Get Started | burger 34 × 34; padding 12/32 (height 59). Compact mode on a wide screen — height 67, like the regular header. The full-width panel below the header opens instantly, without animation: white, a light orange `#fedeac` edge (1 px top, 2 px bottom), a soft shadow; items 48 px each, active and hovered — purple, active in bold.
- **Mobile (≤767):** padding 10/20, height 54 (logo 96 × 29 at ≤576); everything fits down to 320.
- **Phones (≤576, at the user's request):** a full-screen menu below the header bar, items 20/28 centered horizontally and vertically. It scrolls with any number of items, and the first items are not cut off (centering via auto margins rather than justify-content). The tablet dropdown panel is also no taller than the screen and scrolls. While the menu is open, the header bar's blur is removed: `backdrop-filter` makes the bar the containing block for `position: fixed` and was trapping the overlay inside the header.
- **"Ink drop" animation (the user's choice, phones ≤576 only):** the full-screen menu appears as a circle growing from the center of the burger — a light `#f7f7f7` fill (slightly darker than the white header) with an orange `#fdb048` rim. Built with `clip-path: circle()` and a radial gradient driven by a single variable `--aiec-ink` (`@property`, animatable). Opening 0.6 s (ease-out), closing 0.4 s back into the button; items float in one by one (50 ms step, up to 8 steps). Items are dark, active and hovered — purple. A purple fill was tried — too harsh on the eyes. On close, the `aiec-nav-open` class is removed from body only after the animation ends; otherwise the header blur comes back too early and the shrinking drop "jumps" into the header bar (an artifact the user spotted). `prefers-reduced-motion` — no animation.
- **Long-menu safeguard:** if the items don't fit on one line between the logo and the button, the header switches to burger mode on its own at any width (`is-compact`, `ResizeObserver`; tested with 12 items at 1440 and 1100); the panel and the full-screen menu scroll with any number of items.
- **Sub-items:** the widget outputs only the top level; if the menu has sub-items, a warning is shown in the Elementor editor (editor only) and on the "Appearance → Menus" screen. Dropdown submenus — on request.
- **Accessibility:** `nav aria-label="Main menu"`, the burger has `aria-expanded` and `aria-controls`, Esc closes the menu and returns focus, when opened from the keyboard focus moves to the first item (on mouse click or tap it stays on the button, without an outline), page scroll is locked; the focus ring is purple (overrides the black one from Hello's reset); the "skip to content" link comes from Hello.
- **Deviations from the design:** "About US" → "About Us"; the short lines under inactive items are not shown (in the design they are transparent).
- **How the client edits it:** menu items — "Appearance → Menus"; logo, button, layout — Site Parts → Header in Elementor.
- **Publishing:** the "Header" part was published on 2026-10-18 (Elementor MCP `publish-document`); visitors see it instead of Hello's header. The Home (front page), Services, Contact and style guide pages were published at the same time; checked in a logged-out window: all four have our header and footer, the current item is highlighted, all links return 200. About Us and Blogs are placeholder `#` links.
- **Self-check:** 1440 — compared with the reference render (`design/screens/g1-header-compare-1440.png`), coordinates match Figma within 2–3 px; 768 and 375 — closed and open; keyboard; stickiness on scroll; Elementor editor. The animation at 375 was verified by recording frames in real time, without pausing (`g1-ink-375-filmstrip.png`): pausing animations via `getAnimations()` doesn't stop JS timers and produces false frames. At 768 and on the compact desktop (1100, temporary items) the panel has no animations; the edge and colors were checked against computed styles.

- **Decor:** tiles of the logo mark (Figma `1:3348`) — an SVG from the original outlines, cropped to the visible part (186 × 153) and placed as the footer background in the bottom-right corner. Matches the reference render pixel for pixel.

- **How the client edits it:** items — "Appearance → Menus" (Primary and Footer Resources); address, contacts, copyright, button, decor (container background) — Site Parts → Footer in Elementor.

### H1 Home — Hero — accepted 2026-10-18
- **Build:** section `e-flexbox` (`section`, clips the map where it overflows the edges) → `container` → two columns. Text (608 px, over the map): `e-paragraph.badge` → `e-heading` h1 "Simplify Your `<strong>`Crypto Taxes`</strong>` with `<em>`Our Expertise`</em>`" → `e-paragraph.text-lead` → buttons `e-button.btn-primary` (Get Started → Contact) and `e-button.btn-link` ("Discover Our Innovation" → `#innovation`, the anchor will appear in H4). On the right — `e-svg` with the map.
- **Map:** a single 1422 × 608 SVG (`design/assets/home/hero-map.svg`, attachment 90), built by the script `tools/build-hero-map.mjs` from Figma assets (`design/figma/hero`): a coordinate grid, 4151 map dots (vectorized from a 2.2 MB 4096 × 2048 JPEG — one `path`, 24 KB gzipped), 9 labels and 8 arcs. Match with the reference render — 98.3 % of pixels at 1440 (the rest is anti-aliasing and text colors per D17).
- **Animation (at the user's request):** dashes run along the arcs (dash 4/4, period 0.6 s, ≈13 px/s), the labels pulse softly in turn. CSS inside the SVG; under `prefers-reduced-motion` everything stays still. The SVG is inlined in the markup (`e-svg`) rather than used as an image: inside `<img>` the page's media query doesn't reach it (verified — the animation didn't stop). The first version of the dashes didn't move (a keyframe via `var()` — a jump of exactly one period); the user noticed; fixed, and the offset was verified by measurements over time (D21).
- **Top offset:** in the design the navbar (67 px) overlaps the hero; ours is a sticky header of the same height that sits above it, so everything inside is shifted up by 67 px (text — padding 85, the map is built from y = 67) — the badge is at y = 152 from the top of the page, as in Figma. The top of the page (header + hero) at 1440 matches the reference render on 97.5 % of pixels.
- **Buttons:** the link button has no side padding (on desktop and tablet the distance to the primary button is the 24 gap, 34 px to the text in total, as in the design); on mobile the buttons stack and the link sits flush with the left edge (user feedback: with 24 padding it looked misaligned).
- **Desktop (>1200):** the map runs under the text column (grid) and off the right edge, as in the design; on screens wider than 1440 more of it shows on the right.
- **≤1200 (Tablet Extra, the user's decision), tablet and mobile:** stacked — text (up to 720 px), then the map at full width (the grid to the left of the map is cropped: width 132.84 %, offset −32.83 %). Without this, at 1025–1200 only a sliver of the map was left. The empty top strip of the image is cut off with a −7.66 % margin (a share of the column width — it scales by itself at any width), text → map gap 32 (mobile 24): without it there was a noticeable hole under the buttons (user feedback). H1 48/56 down to 1024, then 40/48 and 32/40; lead paragraph 22/30 → 20/28 → 18/26. On phones the labels are small (~11 px) — the user's choice (the whole map rather than a fragment).
- **Deviations from the design:** no divider — in Figma the line has no stroke, and it isn't in the render (the 60 px gap is kept); orange words `#cc7f0c`, lead `#6d6d6d` (D17).
- **How the client edits it:** texts and buttons — in Elementor; the map can be replaced with another SVG (Media Library), the animation lives inside the file.
- **Self-check:** 1440 — compared with the reference render (`design/screens/h1-hero-compare-1440.png`); 1280, 1201, 1200, 1100, 1024, 768, 375 — no horizontal scrolling, the switch at 1200/1201 (`h1-hero-*.png`); animation — `stroke-dashoffset` measured over time and a frame sequence (`h1-dash-frames.png`), `prefers-reduced-motion` (emulated in Playwright); Elementor editor (`editor-parts-fixed.png`: header, hero and footer in the canvas — as on the site).

### H2 Home — Logos — accepted 2026-10-18
- **Build:** section `e-flexbox` (`section`, padding 35, as in the design) → `container` → caption `e-paragraph` (Quicksand Medium 22/28 instead of Roboto per D17, `color-heading`) and the `.logo-marquee` wrapper → row `e-flexbox` → 5 × `e-image.logo-tile` (140 × 56, gap 32). The caption is a paragraph, not a heading.
- **Logos are placeholders (the user's decision):** the kit uses real brands (Webflow, Relume); next to "Trusted by…" this reads as a claim of partnership. Five made-up logos (Company, Studio, BRAND, Agency, Partner): a geometric mark + a word, OFL fonts (Poppins, Righteous, Bebas Neue, DM Serif Display, Archivo Black), letters converted to outlines, `#C8C8C8`. The generator `tools/build-logo-placeholders.mjs` fits the word size to the tile, like the kit's logos. Alt — the name. The client replaces the images in Elementor.
- **Phone (≤767) — marquee (the user's decision):** JS (`src/js/modules/logo-marquee.js`) adds a copy of the logos (hidden from screen readers, without `alt` and `data-id`); the row moves by half its width — exactly one set, so the loop is seamless (the first and last frames match pixel for pixel). Speed 30 px/s with any number of logos; the edges fade out (mask). Tap — pause/resume, mouse hover — pause. Under `prefers-reduced-motion` and in the Elementor editor there is no marquee, just regular wrapping (2 + 2 + 1 on phones).
- **Responsive:** ≥1025 — five in a row; tablet — 3 + 2 (row limited to 500 px), caption 20/28, padding 32; phone — marquee, logos 120 × 48, caption 18/26.
- **Self-check:** 1440 — layout compared with the reference render (`design/screens/h2-logos-compare-1440.png`: caption and tile positions match, the logos are placeholders); 1100, 768, 375 (`h2-logos-sheet.png`); marquee — `transform` measured over time (31 px/s), the loop seam, pause on tap; `prefers-reduced-motion`; editor — no copies.
- **Accessibility (WCAG 2.2.2):** the motion is decorative and stops on tap and with the system setting; there is no separate "pause" button — we'll add one if needed.
